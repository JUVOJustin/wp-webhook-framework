Control webhook behavior, payloads, and delivery using WordPress hooks and filters.

## Actions

### `wpwf_register_webhooks`

Register custom webhooks with the framework registry.

**Parameters:**
- `$registry` (`Webhook_Registry`) - The registry instance

```php
add_action( 'wpwf_register_webhooks', function ( Webhook_Registry $registry ): void {
    $registry->register( new My_Custom_Webhook() );
} );
```

See [Custom Webhooks](./custom-webhooks.mdx) for detailed webhook creation.

### `wpwf_webhook_success`

Fired when a webhook is successfully delivered.

**Parameters:**
- `$url` (string) - The webhook URL
- `$payload` (array<string,mixed>) - The webhook payload
- `$response` (array|WP_Error) - The HTTP response
- `$webhook` (`Webhook`) - The webhook instance

```php
add_action( 'wpwf_webhook_success', function ( string $url, array $payload, array $response, Webhook $webhook ): void {
    error_log( "Webhook '{$webhook->get_name()}' delivered: {$url}" );
}, 10, 4 );
```

### `wpwf_webhook_failed`

Fired for each failed delivery attempt, including retries, before the blocking decision.

**Parameters:**
- `$url` (string) - The webhook URL
- `$response` (array|WP_Error) - The response from wp_remote_post
- `$failure_count` (int) - Current consecutive failure count
- `$max_failures` (int) - Maximum failures before blocking
- `$webhook` (`Webhook`) - The webhook instance

```php
add_action( 'wpwf_webhook_failed', function ( string $url, array $response, int $failure_count, int $max_failures, Webhook $webhook ): void {
    error_log( "Webhook '{$webhook->get_name()}' failed ({$failure_count}/{$max_failures}): {$url}" );
}, 10, 5 );
```

### `wpwf_webhook_blocked`

Fired when a webhook URL is blocked due to reaching the consecutive failure threshold.

**Parameters:**
- `$url` (string) - The webhook URL
- `$response` (array|WP_Error) - The response from wp_remote_post
- `$max_failures` (int) - Maximum failures threshold
- `$webhook` (`Webhook`) - The webhook instance

```php
add_action( 'wpwf_webhook_blocked', function ( string $url, array $response, int $max_failures, Webhook $webhook ): void {
    // Send Slack notification
    wp_remote_post( 'https://hooks.slack.com/services/...', array(
        'body' => wp_json_encode( array( 'text' => "Webhook blocked: {$url}" ) ),
    ) );
}, 10, 4 );
```

See [Notifications](./notifications.mdx) for built-in notification handlers.

## Filters

### `wpwf_payload`

Use this filter to change an event before queuing or immediate delivery. The
built-in handlers supply the [entity fields](#payload-structure) here. The
dispatcher adds `action`, `entity` and `id` to the outgoing body later. It derives
`rest_url` at acceptance for stacked updates and at send time for other deliveries.

Return `false` or `null` to skip the event. Returning an empty array for a
built-in post, term or user payload containing only its default identity fields
keeps the event. Emptying a populated meta or custom payload triggers
`webhook_payload_empty`.

**Parameters:**
- `$payload` (array<string,mixed>) - The webhook payload data
- `$entity` (string) - The entity type (post, term, user, meta)
- `$id` (int|string) - The entity ID

**Returns:** `array<string,mixed>|false|null`

```php
// Skip category events, including changes to category metadata.
add_filter( 'wpwf_payload', static function ( array $payload ): array|false {
    return 'category' === ( $payload['taxonomy'] ?? null ) ? false : $payload;
} );
```

### `wpwf_request_body`

Filter the webhook request body right before sending.

The framework enriches `rest_url` when available. For stacked updates this filter
receives the [stacking format](./update-stacking.mdx), runs once when sealing the
first attempt, and its resulting JSON is retained for retries. The payload argument
is the latest complete event object. Header filters still run per attempt.
Legacy/immediate calls retain their flat body and per-attempt body filtering.

Event fields remain at the root in both modes. For stacked updates, enrich each
event through `wpwf_payload` if the extra fields should also appear in the history.

**Parameters:**
- `$body` (array<string,mixed>) - The full webhook body
- `$action` (string) - The action type
- `$entity` (string) - The entity type (post, term, user, meta)
- `$id` (int|string) - The entity ID
- `$payload` (array<string,mixed>) - The scheduled payload data
- `$webhook` (`Webhook`) - The webhook instance

**Returns:** array<string,mixed>

```php
add_filter( 'wpwf_request_body', function ( array $body, string $action, string $entity, int|string $id ): array {
    if ( isset( $body['rest_url'] ) ) {
        return $body;
    }

    if ( 'post' !== $entity ) {
        return $body;
    }

    $post_type = get_post_type( (int) $id );
    if ( false === $post_type || '' === $post_type ) {
        return $body;
    }

    $post_type_object = get_post_type_object( $post_type );
    if ( ! $post_type_object || true !== $post_type_object->show_in_rest ) {
        return $body;
    }

    $rest_base      = $post_type_object->rest_base ?: $post_type;
    $rest_namespace = $post_type_object->rest_namespace ?: 'wp/v2';
    $body['rest_url'] = rest_url( "{$rest_namespace}/{$rest_base}/{$id}" );

    return $body;
}, 10, 4 );
```

### `wpwf_url`

Filter the webhook URL before scheduling.

**Parameters:**
- `$url` (string) - The webhook URL
- `$entity` (string) - The entity type
- `$id` (int|string) - The entity ID

**Returns:** string

```php
// Route by entity type
add_filter( 'wpwf_url', function ( string $url, string $entity, int|string $id ): string {
    return match ( $entity ) {
        'post' => 'https://api.example.com/webhooks/posts',
        'user' => 'https://api.example.com/webhooks/users',
        default => $url,
    };
}, 10, 3 );
```

### `wpwf_headers`

For stacked deliveries, `wpwf-delivery-id`, `wpwf-window-opened-at` and
`wpwf-window-closed-at` are applied after this filter. They cannot be removed or
changed, including through differently cased names. Other headers remain filterable.

Filter HTTP headers before sending webhook requests.

**Parameters:**
- `$headers` (array<string,string>) - The HTTP headers
- `$entity` (string) - The entity type
- `$id` (int|string) - The entity ID
- `$webhook` (`Webhook`) - The webhook instance

**Returns:** array<string,string>

```php
// Add authentication
add_filter( 'wpwf_headers', function ( array $headers, string $entity, int|string $id, Webhook $webhook ): array {
    $token = get_option( 'api_token' );
    if ( is_string( $token ) && '' !== $token ) {
        $headers['Authorization'] = 'Bearer ' . $token;
    }
    return $headers;
}, 10, 4 );
```

### `wpwf_excluded_meta`

Exclude specific meta keys from triggering webhooks.

**Parameters:**
- `$excluded` (bool) - Whether the current key should be excluded
- `$meta_key` (string) - The current meta key
- `$meta_type` (string) - The meta type (post, term, user)
- `$object_id` (int) - The object ID

**Returns:** bool

**Default excluded:** `_edit_lock`, `_edit_last`, `session_tokens`, and any meta key starting with `_`

```php
add_filter( 'wpwf_excluded_meta', function ( bool $excluded, string $meta_key, string $meta_type, int $object_id ): bool {
    if ( '_my_internal_field' === $meta_key ) {
        return true;
    }

    return $excluded;
}, 10, 4 );
```

### `wpwf_blocked_notification_email`

Filter blocked notification email data. Return `false` to prevent email.

**Parameters:**
- `$email_data` (array{recipient: string, subject: string, message: string, headers: array, url: string, error_message: string, response: mixed})
- `$url` (string) - The webhook URL that failed
- `$response` (mixed) - The response from wp_remote_post

**Returns:** array|false

```php
// Custom recipient
 add_filter( 'wpwf_blocked_notification_email', function ( array $email_data, string $url, mixed $response ): array {
    $email_data['recipient'] = 'webhooks@example.com';
    return $email_data;
}, 10, 3 );

// Disable email notifications
 add_filter( 'wpwf_blocked_notification_email', fn() => false );
```

### `wpwf_max_consecutive_failures`

Filter the maximum consecutive failures threshold before URL blocking.

**Parameters:**
- `$max_failures` (int) - The threshold
- `$webhook_name` (string) - The webhook name

**Returns:** int

```php
add_filter( 'wpwf_max_consecutive_failures', function ( int $max_failures, string $webhook_name ): int {
    return 'critical_webhook' === $webhook_name ? 3 : $max_failures;
}, 10, 2 );
```

### `wpwf_timeout`

Filter webhook request timeout in seconds.

**Parameters:**
- `$timeout` (int) - The timeout (1-300)
- `$webhook_name` (string) - The webhook name

**Returns:** int

```php
add_filter( 'wpwf_timeout', function ( int $timeout, string $webhook_name ): int {
    return 'bulk_sync_webhook' === $webhook_name ? 120 : $timeout;
}, 10, 2 );
```

### `wpwf_delivery_mode`

Filter the webhook delivery mode.

**Parameters:**
- `$delivery_mode` (string) - The configured mode value (`scheduled` or `immediate`)
- `$webhook_name` (string) - The webhook name

**Returns:** string

```php
use juvo\WP_Webhook_Framework\Delivery_Mode;

add_filter( 'wpwf_delivery_mode', function ( string $delivery_mode, string $webhook_name ): string {
    if ( 'critical_webhook' !== $webhook_name ) {
        return $delivery_mode;
    }

    return Delivery_Mode::IMMEDIATE->value;
}, 10, 2 );
```

### `wpwf_retry_base_time`

Filter the base time (seconds) for exponential backoff. Default: 60.

**Parameters:**
- `$base_time` (int) - Base time in seconds
- `$webhook_name` (string) - The webhook name
- `$retry_count` (int) - Current retry attempt

**Returns:** int

### `wpwf_retry_delay`

Filter the final calculated retry delay.

**Parameters:**
- `$delay` (int) - Calculated delay in seconds
- `$retry_count` (int) - Current retry attempt
- `$webhook_name` (string) - The webhook name

**Returns:** int

```php
// Static 5-minute delay
add_filter( 'wpwf_retry_delay', fn() => 300 );
```

## Payload Structure

A receiver can identify a deleted post from the body even after WordPress
removes the resource. For example, a deletion of a custom post type with REST
support disabled sends the following body.

```json
{
  "action": "delete",
  "entity": "post",
  "id": 123,
  "post_type": "product",
  "slug": "spring-collection"
}
```

Built-in create, update, and delete events capture the following fields before
the payload filter runs. Scheduled deliveries retain their event-time values.

| Entity | Default fields |
| --- | --- |
| Post | `post_type`, `slug` |
| Term | `taxonomy`, `slug` |
| User | `roles` (array), `username` (WordPress login) |

For trashed posts, `slug` uses the original slug when WordPress retained it.
A draft that never had a slug can send an empty string.

Meta events include `meta_type` and `meta_key` plus the available parent
identity. A bulk deletion by meta key has no individual parent to identify.
During user deletion, WordPress removes metadata row by row. Once it removes
the capabilities row, subsequent meta events can carry an empty `roles` list.
The final user delete uses the user object retained by WordPress.

With [update stacking](./update-stacking.mdx), each entry in `aggregated_events`
contains the identity captured for that event. With legacy scheduling, the first
matching pending event supplies the identity for that delivery.

## Filter Priority

Filters are applied in this order:

1. `wpwf_delivery_mode` - Resolve scheduled vs immediate mode
2. `wpwf_url` - Customize webhook URL
3. `wpwf_payload` - Modify or prevent payload
4. `wpwf_request_body` - Modify final request body before send
5. `wpwf_headers` - Customize HTTP headers
6. `wpwf_excluded_meta` - Filter meta keys (meta webhooks only)

### Internal stacking clock

`wpwf_stack_time` supplies UTC epoch seconds for deterministic stacking tests.
Production uses `time()`; integrations should not alter it to change window length
or schedule delivery. The aggregation interval remains fixed at 60 seconds.
